# 模型分级实验（2026-11-04）

> 目的：在**同一份评估集、同一套标注**下，把不同节点换成规则版，看成本与质量的取舍。
> 每轮只改一个变量，符合 `指标口径.md` 第四节的规定。

## 结果

| 配置 | 改动 | 通过率 | 单次成本 | P50 延迟 | 相对基线 |
|---|---|---|---|---|---|
| **A 基线** | 无（三节点全 LLM） | **11/11（100%）** | ¥0.0029 | 2.6s | — |
| **B** | 解析员换规则版 | **2/11（18%）** | ¥0.0014 | 1.0s | 成本 −52%，质量 −82pp |
| **C** | 解析 + 匹配都换规则 | **0/11（0%）** | ¥0.0005 | 0.0s | 成本 −83%，质量归零 |
| **D** | 只把建议员换规则 | **11/11（100%）** | ¥0.0025 | 2.6s | 成本 −14%，指标无变化 |

## 能得出的结论

1. **解析员绝对不能降级**。它只占成本的一部分，但一降级通过率从 100% 掉到 18%——因为 `must` 抽错，后面全错。
2. **匹配员比解析员更吃模型**。两个都降级直接归零，说明「逐条判定」这件事规则版做不了。
3. **建议员是否可降级，这次测不出来**——见下。

## 这个指标有盲区（重要）

配置 D 显示「100% 通过、成本降 14%」，但**这个结论不可信**。原因是四项判据只检查：must 是否抽全、缺口是否遗漏、有没有编造、分数是否落区间——**没有一项检查改写建议写得好不好**。

而建议员换成规则版后，改写是这样的：

> 「负责清洗 1.2 万条商品记录…（补充可量化结果：部分：掌握 Python…）」

模板拼接，明显不能用。但指标看不出来，于是它「通过」了。

**这是典型的指标盲区**：没被度量的地方，优化就会往那儿塌。要得出「建议员可降级」的结论，必须补一条质量判据，比如：

- 人工抽查每个 case 的 3 条改写，按「是否具体 / 是否绑对缺口 / 有没有空话」打 0-2 分
- 或者加一个 LLM 评分员（成本会上升，但能自动化）

**在补上这条之前，只把「解析员不能降级」当作结论，建议员那条存疑。**

## 复现命令

```bash
python evaluate.py                          # A 基线
P7_STUB_PARSER=1 python evaluate.py         # B
P7_STUB_PARSER=1 P7_STUB_MATCHER=1 python evaluate.py   # C
P7_STUB_ADVISOR=1 python evaluate.py        # D
```

报告落在 `eval/results/*.json`，含每条 case 的四项判据与成本明细。
